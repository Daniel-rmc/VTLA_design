你的研究主线应该从“把触觉图片接进 VLA”升级为：

> 研究触觉是否提供了视觉和本体状态无法提供的接触隐状态，以及由触觉驱动的演示能否让机器人学会接触后的闭环纠偏。

你现在拥有的三类数据，其价值并不相同。

## 三种采集方式的定位

| 数据来源 | 人的动作依据 | 最适合学习 | 主要风险 |
|---|---|---|---|
| VR 纯视觉遥操作 | 外部视觉 | 接近、抓取、粗对准、成功轨迹先验 | 触觉没有因果驱动动作 |
| 人工拖拽/示教 | 人能感受到机器人接触力 | 接触后调整、卡住恢复、柔顺运动 | 测量轨迹混入机器人柔顺性和动力学 |
| 触觉 UMI | 人直接感受手持装置的接触 | 可规模化采集触觉驱动动作 | UMI 与机器人传感器、动作、夹爪存在域差异 |

因此，现有 1,508 条 VR 成功演示不应该废弃，但它们更适合训练全局视觉策略，而不是证明触觉闭环控制有效。

真正有触觉研究价值的数据应主要来自：

- 人工拖拽的力反馈示教；
- 触觉 UMI；
- 有意识采集的偏位、卡住和恢复轨迹。

## 触觉作用应该拆成三层

### 1. 接触事件与任务阶段

触觉可以帮助判断：

- 是否建立了抓取接触；
- peg 是否碰到孔沿；
- 是否从 free-space 进入 contact-rich 阶段；
- 是否可能已经完成插入。

但“发生接触”和“正确接触”不是一回事。

正确接触还需要结合视觉、末端位姿、任务目标和后续结果。错误碰撞、卡死和成功插入都可能产生很强的触觉信号。

所以这个模块应该预测：

```text
contact event
task phase
contact quality
```

而不是只预测一个含义模糊的 `contact_probability`。

### 2. 接触隐状态估计

这是触觉最不可替代的作用。指尖触觉可能间接编码：

- peg–hole 接触方向；
- 法向力和切向力；
- 左右受力不对称；
- 物体在夹爪内的微小位姿；
- 滑移；
- 卡住或楔紧；
- 调整后受力变好还是变坏。

这类信息在视觉中通常被遮挡，却直接决定下一步该向哪个方向调整。

### 3. 接触后的闭环修正

真正目标不是“检测到接触”，而是：

```text
触觉状态变化
→ 判断误差方向
→ 产生小幅修正动作
→ 观察新的触觉状态
→ 继续修正或结束
```

因此，触觉最重要的性能指标应该是：

- 偏位后的恢复成功率；
- 接触后纠偏时间；
- 峰值接触力和力冲量；
- 卡死率；
- 成功插入率；
- 对视觉遮挡和孔位误差的鲁棒性。

而不是单独看 `contact_probability`。

## 什么才是“正确的触觉数据”

### 必须记录的信号

建议以后每条数据同步记录：

```text
外部/腕部 RGB
原始触觉视频
无接触参考帧
机器人测量位姿和关节
实际控制器下发命令
夹爪宽度/命令
腕部六维力矩（采集阶段强烈建议）
任务成功/失败
采集方式和操作者
统一单调时钟 timestamp
```

你的当前 28D state 只有关节和末端位姿，没有力信息，见 [数据定义](/home/rmc/workspace/manipulationNet/peg_in_hole/15holes_v3/meta/info.json)。力矩传感器可以只在采集和训练时作为 privileged supervision，部署时仍然只使用视觉触觉。

这正是 TacUMI 选择同时采集 ViTac、力矩和位姿的原因：力矩不一定是最终策略输入，但可以给触觉表示、contact event 和阶段切分提供可信监督。[TacUMI 原始论文](https://arxiv.org/abs/2601.14550)

### “可以假设同步”是不够的

10 Hz 下，100 ms 就错一帧。必须测量：

- 相机曝光时间；
- 触觉帧时间；
- action command 时间；
- measured state 时间；
- 控制器执行延迟。

建议通过人为敲击、快速夹爪接触等明显事件，对触觉变化、力矩峰值和状态变化做互相关，估计各模态 offset。训练时再统一重采样。

还应该做 tactile shift ablation：

```text
T(t-3), T(t-2), T(t-1), T(t), T(t+1)
```

如果使用未来触觉反而效果最好，说明数据存在时序泄漏或对齐错误。

### 触觉不应只保存一张当前图像

当前 VTLA 是 `n_obs_steps=1`，不能明确知道压力是在增加还是减小。你的假设恰恰依赖触觉变化，因此建议保留原始高帧率触觉流，输入短时间窗口：

```text
I(t-k:t), I(t)-I(reference), I(t)-I(t-1)
```

Sparsh 的实验也发现，触觉背景处理和短时序窗口对可泛化表示很重要，并证明自监督预训练比有限数据端到端学习更具数据效率。[Sparsh 原始论文](https://arxiv.org/abs/2410.24090)

如果千觉传感器原生帧率高于 10 Hz，不要在采集时先丢帧；先保存原始流，训练时再下采样。

## 动作应该怎样表示

不要直接对 quaternion 各元素相减。建议使用当前末端坐标系中的相对 SE(3) 轨迹：

```text
ΔT(t,h) = inverse(T(t)) · T(t+h)
```

平移使用局部坐标，旋转使用 rotation vector、6D rotation 或 Lie algebra log map，再预测夹爪目标或增量。

具体建议：

- 机器人遥操作：优先保存实际 command，measured pose 单独作为 observation；
- 拖拽示教：没有 command 时，可以把未来测量轨迹当示教目标，但必须记录这是 kinesthetic 数据；
- UMI：使用相对末端轨迹，并做 collection/deployment latency matching。

原始 UMI 也把 relative trajectory action representation 和 latency matching 当成可部署转移的重要条件。[UMI 原始论文](https://umi-gripper.github.io/umi.pdf)

对于接触调整，50-step、10 Hz 相当于预测未来 5 秒，过长。即使当前每次只执行第一步，远期监督对接触状态来说仍可能不确定。建议 contact-local policy 使用更短的 0.5–1 秒 action horizon。

## 推荐的模型结构

你当前最适合的不是一个完全混合的单体 VTLA，而是“全局视觉策略 + 局部视触觉策略”：

```text
                 ┌─ global policy(V, S, task)
视觉、状态、任务 ─┤   负责接近、抓取、粗对准
                 │
触觉时间历史 ────┼─ phase/contact-quality estimator
                 │
                 └─ local tactile residual
                     负责接触后微调、恢复、停止
```

动作形式：

```text
a = a_global + g_phase × Δa_tactile
```

建议训练顺序：

1. 用现有 VR 数据训练 `Vision + State` base policy；
2. 冻结或部分冻结 base；
3. 用拖拽和触觉 UMI 的 contact-rich 数据训练 temporal tactile encoder 和 residual；
4. 用力矩监督 contact/phase/force proxy；
5. 最后小学习率联合微调。

这样可以避免当前 main head 和 tactile residual 任意分摊动作的问题。

ViTaL 近期工作也采用了类似的任务分解：全局阶段依赖视觉语义定位，局部接触阶段使用视触觉策略。[ViTaL 原始论文](https://arxiv.org/abs/2506.13762)

## 应该怎样采集失败和恢复

不要只采“自然发生的随机失败”。建议人为构造可控扰动：

- peg 相对孔左/右/前/后偏置；
- 不同角度误差；
- 轻碰孔沿；
- 侧向挤压；
- 部分插入后卡住；
- 夹持松紧变化；
- 小幅滑移；
- 错误接触后退出再插入；
- 不可恢复状态下安全 abort。

每种轨迹标记阶段：

```text
approach
first_contact
adjustment
insertion
success
failure/abort
```

最关键的是主动制造：

```text
视觉和末端位姿非常接近
但触觉状态不同
且正确动作也不同
```

这类数据才能真正迫使模型使用触觉。

## 最小实验矩阵

建议先验证五个假设：

| 假设 | 对照实验 |
|---|---|
| 触觉主要改善接触后而非接触前 | 分阶段比较 V+S 与 V+S+T |
| 触觉驱动的演示更有效 | 同预算比较 VR、拖拽、触觉 UMI |
| 时间变化比单帧更重要 | 单帧 vs 4/8 帧历史 |
| 模型真的使用了触觉 | 正常、置零、同阶段 shuffle、时间延迟 tactile |
| residual 分解有效 | 单体融合 vs 冻结 base + tactile residual |

真实机器人评估至少报告：

```text
任务成功率
接触后恢复率
峰值力/力冲量
卡死率
完成时间
纠偏次数
新孔位/新物体泛化
```

并在相同训练数据量、相同初始扰动分布下比较。单纯 offline action L1 不足以证明 tactile manipulation 性能。

## 最值得先做的一步

先不要马上重构大模型。做一个约 200–300 条的 instrumented pilot dataset：

- 同一个 peg-in-hole 任务；
- 一部分拖拽示教，一部分触觉 UMI；
- 同时采触觉、腕部力矩、command、measured state；
- 包含正常成功、偏位恢复、卡死恢复和失败；
- 原始高帧率保存；
- 严格测量同步；
- 使用与机器人部署端相同的千觉传感器、指尖结构和安装方向。

然后先回答三个问题：

1. 触觉历史能否预测接触方向、力或任务阶段？
2. 在固定视觉/位姿后，触觉能否预测专家调整方向？
3. 加触觉是否只在扰动和恢复条件下提高真实成功率？

这三个问题成立之后，再扩展成真正的触觉 VLA。否则继续扩大模型，很可能只会让触觉成为“任务进度提示器”，而不是物理反馈通道。
